# PharmaFind — Phase 1 setup

Find a medicine, see which pharmacies near you have it, and see alternatives with the same active ingredient.
Phase 1 = project skeleton + database + demo data.

| Tool | Where | Notes |

## How the database supports the 3 features

- **Find a pharmacy** → `stock` links each pharmacy to each medicine with price and quantity; `pharmacies` has lat/lng for distance sorting (Phase 2).
- **Alternatives** → every medicine has `active_ingredient` + `strength` + `form`. Same three values = same medicine from another company.
- **What's inside / what it's for** → `active_ingredient` and `general_use` come from the database, not generated by AI.

# Phase 2 — Search, distance, map

## What's new

| File | What it does |
|---|---|
| `search.py` | Typo-tolerant search in English, Arabic and Kurdish; Haversine distance |
| `app.py` | New routes: `/api/search` and `/api/medicines/<id>/pharmacies` |
| `templates/index.html` | The real app page (old check page moved to `/check`) |
| `static/style.css`, `static/app.js` | Design and front-end logic |
| `static/vendor/leaflet/` | Map library, bundled locally so it works on bad Wi-Fi |

## New API routes

- `/api/search?q=panadl` → ranked matches with a score (0–100) and which field matched
- `/api/medicines/1/pharmacies?lat=35.56&lng=45.43&sort=distance` → pharmacies that have it in stock, nearest first (`sort=price` for cheapest)

## How the search works

1. **Normalize** the query and every name: lowercase, remove Arabic diacritics, and map letter variants to one form (ی/ي, ک/ك, ە/ة/ه, ۆ/و, أ/إ/آ → ا…).
2. **Score** each medicine against its brand, Arabic, Kurdish and ingredient names: exact = 100, starts with = 92, contains = 85, otherwise a similarity ratio (handles typos).
3. Keep matches scoring 60+, best first.

Distance uses the **Haversine formula** (straight-line distance on the Earth's surface).

## Demo tips

- Click anywhere on the map to set "your location". Don't rely on laptop GPS at the venue.
- The map tiles need internet. Everything else works offline.

# Phase 3 — Alternatives and medicine info

## What's new

- **Tabs** under each medicine: Pharmacies · Alternatives · About.
- **Alternatives** (`/api/medicines/<id>/alternatives?lat=&lng=`):
  - *Same medicine, other companies*: same active ingredient(s) **and** strength **and** form. A direct swap.
  - *Same ingredient, different strength or form*: shown with a warning to ask the pharmacist.
  - Combination medicines only match the exact same combination (Panadol Extra is **not** an alternative to Panadol).
  - Each alternative shows how many pharmacies have it, the nearest one, and the lowest price.
- **Sold-out banner**: if no pharmacy has the medicine, the app says so and offers a button to the alternatives.
- **About tab**: ingredients (split for combinations), strength, form, company, what it's used for, prescription note, disclaimer. All from the database, nothing generated.

## Demo scenario

`DEMO_OUT_OF_STOCK = ["Zyrtec"]` in `seed_data.py` makes Zyrtec sold out everywhere.
Search **Zyrtec** → "sold out" → **Show alternatives** → generic Cetirizine is 270 m away.
Change the list to demo with a different medicine, then run `python seed.py`.

## How matching works (`search.py`)

- `ingredient_key()` turns "Amoxicillin + Clavulanic acid" into the set {amoxicillin, clavulanic acid}, so order and spelling case don't matter.
- `strength_key()` makes "500 mg" and "500mg" equal.
- `compare_medicines()` returns `exact`, a list of differences (`strength`, `form`), or nothing.

# Phase 4 — AI scanner

## Install (once)

```powershell
venv\Scripts\activate
pip install -r requirements.txt
```
This adds **numpy**, **opencv-python-headless** (computer vision + runs the OCR neural networks)
and **zxing-cpp** (barcodes). No onnxruntime/torch needed, so it works on Python 3.15.
The OCR models (13 MB) are already in `ai/models/`.

Your box photos must be in `photo/<folder>/`, and each folder name must be listed in
`PHOTO_FOLDERS` at the bottom of `seed_data.py`.

## How to use it

Press **Scan** next to the search box.

- **Barcode:** hold the box's barcode in front of the camera. The app checks ~3 frames per
  second and opens the medicine as soon as it reads a known barcode (beep + message).
- **Recognize the box:** show the front of the box and press the button. The app reads
  the text and compares the box with your photos, then shows up to 3 answers with a
  confidence (Sure / Likely / Not sure). Click the right one.
- **Upload a photo:** same as above, from a file (or the phone camera).

The first time after starting the server, the app builds its photo index (~20–60 s).
After that it's cached in `instance/visual_index.pkl` and starts in about a second.
If you add or change photos, the index rebuilds automatically.

## How the AI works (`ai/`)

| File | Method | What it does |
|---|---|---|
| `barcodes.py` | zxing-cpp | Reads EAN-13 / Code 128 / GS1 DataMatrix. Exact. |
| `ocr.py` | Deep learning (PP-OCRv3: a DB text detector + a CRNN recognizer with CTC decoding), run with OpenCV DNN | Reads the text printed on the box. |
| `visual.py` | Computer vision (SIFT keypoints + ratio test + RANSAC homography) | Compares the image with the reference photos. Points that also appear in photos of *other* medicines (counter, pen, hand) are removed as background. |
| `recognizer.py` | Combines them | Barcode first. Otherwise each medicine gets a text score (brand name words found, fuzzy, bigger/central text counts more; generic names and wrong numbers count less) and a visual score; they're combined into one confidence. A visual match counts **alone** only with ≥20 matching points and 2× the runner-up; otherwise only as support for the text. |

API: `POST /api/scan/frame` (fast barcode check), `POST /api/scan/photo` (full recognition),
`GET /api/scan/status` (are the models loaded?). Both POSTs take an image in the `image` form field.

## Measured accuracy (`python evaluate.py`)

On the 81 photos of 16 boxes (each photo tested with itself removed from the reference set):

| Mode | Correct |
|---|---|
| Full (barcode + text + visual) | **75/81 = 93%** — 5 of the 6 misses say "not recognized" (side views), only 1 is a wrong answer |
| Box front only (no barcode) | 68/81 = 84% |
| Reading the name only (like a box we never photographed) | 49/81 = 60% (includes side/back views and Arabic-only boxes) |

False matches: with each medicine removed from the index (so its photos are "unknown boxes"),
and on the two showcase posters, the visual rule gave **0 false matches out of 42**.
About 0.9 s per photo on the test machine.

Be honest on stage: photos taken seconds apart look alike, so real accuracy with a new
camera and background will be somewhat lower. Test with your webcam before the showcase.

## Demo tips

- Good light, box about 20–30 cm from the webcam, front facing the camera.
- Barcode is the fastest and safest: start the demo with it (Gasec barcode → sold out → Ome TAD).
- Then show "Recognize the box" with a front (e.g. Fexet, Piodol), and an Arabic-only box
  (Clavmark / Claritine) to show the visual matching.
- The camera only works on `http://127.0.0.1:5000` (browsers allow cameras on localhost or https).

## Adding a new box

1. Add the medicine to `MEDICINES` (and its barcode to `BARCODES`) in `seed_data.py`.
2. Put 4–6 photos in `photo/<FolderName>/` and add `"<FolderName>": "<brand_name>"` to `PHOTO_FOLDERS`.
3. `python seed.py`, restart `python app.py`.

# Phase 5 — Pharmacist dashboard

Open **http://127.0.0.1:5000/pharmacy** (or click "For pharmacies" in the app's header).

## Demo logins

Every pharmacy has an account: username = first word of its name in lower case,
password **`pharma123`** (set in `seed_data.py` → `DEMO_PASSWORD`).
`python seed.py` prints the full list: shifa, hayat, nawroz, bakhtiari, azadi, ...
**Shifa** is the pharmacy nearest the city centre, so it's the best one to demo.

## What it does

**Overview** (choose the last 7/14 days and an area of 1/3/5 km around the pharmacy):
- Searches near you, and how many used the AI scanner.
- **Missed demand**: medicines people nearby searched for that this pharmacy doesn't have
  (not sold, or out of stock), with an "Add to stock" button.
- Searches per day, most searched medicines near you (with your stock status),
  medicines running low (≤ 5 boxes), and searches for medicines not in PharmaFind at all.

**My stock**:
- Edit price and quantity directly in the table (or with − / +). It saves by itself.
- "City average" shows how your price compares with other pharmacies (▲ above / ▼ below by more than 15%).
- Add a medicine (the city's average price is suggested), or remove one (click twice).
- Changes appear in the public app immediately, with "updated just now".

## How it works

- `pharmacy_routes.py` (a Flask Blueprint): login, stock and insights API.
- Passwords are stored **hashed** (Werkzeug scrypt), never in plain text.
- The login is a signed session cookie (`HttpOnly`, `SameSite=Lax`, 12 hours); the signing key is
  created once in `instance/secret_key`, which is not in Git.
- Requests that change data must send `X-Requested-With: fetch`, which blocks forged
  cross-site form posts. Every query only touches the logged-in pharmacy's own rows.
- The public app now sends the user's location with each search and scan; it's **rounded to
  about 100 m** before saving (`log_search` in `app.py`), which is enough for "searches near you".
- The search history in the dashboard is **demo data** (`seed_searches` in `seed.py`,
  700 searches over 14 days plus searches for medicines we don't have). Real searches you make
  in the app are added on top.

## The live demo

1. In the public app, scan or search **Gasec** → "sold out everywhere".
2. In the dashboard, log in as **shifa** → Missed demand shows *Gasec · 23 searches* → **Add to stock** → Save.
3. Back in the app, search Gasec again → Shifa Pharmacy has it, "updated just now".

Run `python seed.py` before the showcase to reset everything (Gasec sold out again).

# Phase 6 — Customer accounts (branch `phase6`)

Built **after** the showcase plan, on its own Git branch. The `main` branch (the showcase
version, and what Render runs) does not have it.

## What's new

- A **Log in** button in the header (just a person icon on phones).
- Log in with your **mobile number + a 6-digit code**. No password. The first login makes the account,
  so "log in" and "sign up" are the same thing. **Name, age and gender are required** (Phase 7):
  the account can't reserve medicines until they are filled in.
- **Guests keep everything**: search, scan, alternatives and info need no account.
  The account is for ordering medicines (Phase 7).
- Works in Kurdish, Arabic and English, and accepts Kurdish/Arabic digits (٠٧٧٠… or ۰۷۷۰…).

## Try it

1. `python app.py`, open http://127.0.0.1:5000, click **Log in**.
2. Type a number like `0770 123 4567` → **Send me a code**.
3. There is no SMS yet ("test mode"): the code is shown in a **yellow box** on the page and
   printed in the terminal. Type it; you are logged in as soon as the 6th digit is typed.

## How it works (`account_routes.py`)

| API | What it does |
|---|---|
| `POST /api/account/send-code` `{phone}` | makes a random 6-digit code and "sends" it |
| `POST /api/account/verify` `{phone, code}` | checks it and logs in (makes the account if new) |
| `GET /api/account/me` | who is logged in (`{"user": null}` for guests) |
| `PUT /api/account/me` `{name}` | change your name |
| `POST /api/account/logout` | log out |

- New tables: `users` (phone, name, verified, created_at, last_login_at) and `login_codes`.
- Only a **hash** of each code is saved (HMAC-SHA256 with the app's secret key).
- A code works for **5 minutes**, **once**, and dies after **5 wrong tries**.
- Limits against SMS spam: 1 code per number per minute, 5 per number per hour, 20 per internet address per hour.
- Customers stay logged in for 30 days; pharmacist logins still end after 12 hours.
  Logging in or out as a pharmacist does not log the customer out (and the other way round).
- `python seed.py` now resets **only the demo tables**. Accounts are kept.

## Database: SQLite on the laptop, PostgreSQL online

- With nothing set, it uses `instance/pharmafind.db` (SQLite) like before.
- Set **`DATABASE_URL`** to a PostgreSQL address and it uses that instead. This matters online:
  Render's free plan wipes the SQLite file on every restart, so accounts would disappear.
  The Dockerfile installs the PostgreSQL driver (`psycopg`); the laptop doesn't need it.
- Which PostgreSQL host to use is decided when Phase 6 goes online (after the showcase).

## Settings

| Setting | Meaning |
|---|---|
| `DATABASE_URL` | PostgreSQL address. Empty = SQLite file. |
| `OTP_PROVIDER` | how codes are sent. Only `console` exists today (printed in the terminal). |
| `OTP_SHOW_CODE=1` | also show the code on the page on the live website. **Demo only, never with real users.** |

# Phase 7 — Reserve and pick up (branch `phase6`)

## What's new

**Customers**
- Every pharmacy in the results has a **Reserve** button. (Prescription medicines too since Phase 8,
  with a photo of the prescription. Controlled medicines never.)
- A **basket** button appears at the bottom. One reservation = **one pharmacy**, at most 5 boxes of each medicine.
- **Send reservation** asks you to log in, and to fill in **name, age and gender** if they're missing
  (all three are required). Then it sends the reservation by itself.
- **My reservations** (in the account pop-up) shows each reservation, its status and a big **4-digit pickup code**.
  It refreshes every 20 seconds.
- You pay **at the pharmacy** when you collect it. No online payment.

**Pharmacists** (dashboard → new **Reservations** tab, with a red number for new ones)
- See the customer's **name, age, gender and phone**, the medicines, the total and the note.
- **Confirm** (the boxes are taken off your stock) or **Reject** (out of stock / other reason).
- **Mark as ready**, then type the customer's **pickup code** → **Collected**.
- The pharmacist does **not** see the pickup code: the customer has to show it.

## The rules (`order_routes.py`)

| Rule | Value |
|---|---|
| Medicines per reservation | one pharmacy, up to 10 medicines, up to 5 boxes each |
| Open reservations per customer | 3 |
| Kept after the pharmacy confirms | 24 hours, then it expires and the boxes go back to the stock |
| No answer from the pharmacy | expires after 24 hours |
| Prescription medicines | with a photo of the prescription, checked by the pharmacist (Phase 8) |
| Controlled medicines (tramadol, pregabalin, …) | never online (`CONTROLLED_INGREDIENTS` in `seed_data.py`) |
| Minimum age for an account | 12 (`MIN_AGE` in `account_routes.py`) |

Statuses: `pending` (waiting) → `confirmed` → `ready` → `picked_up`, or `cancelled` / `expired`.
When two people click at the same moment (customer cancels while the pharmacist confirms), only one
wins, and the stock stays correct.

## Database

- New tables `orders` and `order_items`; new columns `users.birth_year`, `users.gender`, `medicines.controlled`.
- We ask for the **age** but save the **year of birth**, so the age is still right next year.
- An older database gets the new columns automatically when the app starts (`add_missing_columns` in `models.py`).
- `python seed.py` also deletes the reservations (they belong to the demo pharmacies). Accounts stay.
- `python seed.py --if-empty` only fills an empty database. `start.sh` uses it when `DATABASE_URL`
  (PostgreSQL) is set, so restarting the website doesn't wipe accounts and reservations.

# Phase 8 — Prescription check (branch `phase6`)

The app **can't prove** a prescription is real. The **pharmacist** checks it; the app carries the proof
to them, makes sure the check really happens, and stops the same prescription being used twice.
At pickup the **original paper** is the real proof: the pharmacist keeps or stamps it.

## What's new

**Customers**
- Prescription medicines now have a **Reserve** button too (a purple note explains what is needed).
- The basket shows **Prescription photo (required)**: take or choose a photo of the whole prescription.
  It can't be sent without one.
- **My reservations** shows "Prescription: being checked / approved / not accepted", and "See my photo".
- When it's confirmed: "Bring the original prescription paper with you."

**Pharmacists** (Reservations tab)
- A **Prescription** badge, the **photo** (tap it for a big view, click to zoom) and a **checklist**:
  doctor's stamp and signature · date within 30 days · it's for this patient · the medicine is written on it.
- They must tick all four and write the **doctor's name** and the **date**, then **Prescription OK, confirm**.
- Or **Reject** with a reason: photo not clear · not a valid prescription · name or medicine doesn't match ·
  already used.
- At pickup they must tick **"I took (or stamped) the original prescription paper"**, as well as typing the pickup code.

## How re-use is stopped ("one prescription = one use")

| Trick | What happens |
|---|---|
| Send the very same photo file again (any pharmacy) | blocked when sending (exact fingerprint, SHA-256) |
| Send the same photo re-saved or resized | allowed, but the pharmacist sees a **warning** ("a very similar photo was sent before, reservation #…") |
| Take a new photo of the same paper | pharmacist can't approve: same customer + same doctor + same date was already used |
| Use the paper in the pharmacy after reserving | the pharmacist keeps or stamps the original at pickup |

A prescription from a **cancelled or expired** reservation is free again (no medicine was handed over).
The "looks the same" check is only a warning, because prescriptions from the same doctor's pad can look alike.

## Privacy

- The photo is stored **inside the database**, never at a public web address.
- Only the **customer** and the **one pharmacy** it was sent to can open it (other pharmacies, other customers
  and guests get "not found"). It is never cached by the browser.
- Before saving, the photo is made smaller (max 1600 px) and saved again. That removes the **hidden phone data**
  (EXIF: GPS location, phone model).
- The photo is **deleted** as soon as the reservation is finished (collected, cancelled, rejected or expired).
  Only the fingerprints, the doctor's name and the date are kept, for the "one use" rule.

## Files and settings

- `prescriptions.py`: cleans the photo, makes the fingerprints, finds re-use.
- `order_routes.py`: `RX_MAX_AGE_DAYS = 30` (how old a prescription may be; **ask a pharmacist** what is right),
  new reject reasons, photo addresses `/api/orders/<id>/prescription` and `/api/pharmacy/orders/<id>/prescription`.
- New table `prescriptions` (made automatically on start).

# Phase 9 — Delivery by drivers, cash at the door (branch `phase6`)

Like Talabat: a driver brings the reservation to the customer's home. The checks happen at the door,
and payment is **cash** (no online payment). Prescription medicines can be delivered too: the driver
must check and take the **original paper** at the door.

> **Check the law first.** Before this is used with real people, ask a pharmacist or the Pharmacists
> Syndicate whether delivering medicines (especially prescription ones) is allowed in the Kurdistan Region.

## How a delivery goes

1. **Customer**: basket → **Delivery** → writes the address (area, street, house, landmark) and sets the
   location on the map → sees the fee → **Send reservation**. Payment: cash to the driver.
2. **Pharmacist**: confirms (and checks the prescription photo, Phase 8) → **Mark as ready**.
3. **Driver** (`/driver`): sees the job: pharmacy, distance, fee and cash to collect, but **not** the
   customer's name, phone or address. Taps **Take this job** (first driver wins). Now sees the customer.
4. **Pharmacist**: the driver arrives → **Given to Aram Omar** → *out for delivery*.
5. **Driver at the door**: for prescriptions, checks the original paper shows the doctor, date and patient
   the pharmacist wrote down, and takes it · ticks **cash collected** · types the customer's
   **4-digit code** → **Delivered**. Or **Couldn't deliver?** (not home / no prescription paper /
   refused / other) → the reservation is cancelled and the boxes go back to the stock.
6. **Customer** sees every step in **My reservations**: confirmed → driver collecting → on the way
   ("have 24,000 IQD in cash ready") → delivered.

## Rules

| Rule | Value (in the code) |
|---|---|
| Delivery fee | 2,000 IQD up to 3 km, then +500 IQD per km (`DELIVERY_*` in `order_routes.py`) |
| Furthest delivery | 15 km from the pharmacy |
| Jobs a driver can carry at once | 3 (`MAX_ACTIVE_JOBS` in `driver_routes.py`) |
| Cancel while out for delivery | not possible (customer or pharmacy) |
| Driver sees the prescription photo | **never**: only doctor, date and patient's name |
| Payment | cash only. The driver gives the medicine money to the pharmacy and keeps the fee (not tracked in the app yet) |
