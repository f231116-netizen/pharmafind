# PharmaFind — Phase 1 setup

Find a medicine, see which pharmacies near you have it, and see alternatives with the same active ingredient.
Phase 1 = project skeleton + database + demo data.

## 1. Install the tools (once)

| Tool | Where | Notes |
|---|---|---|
| Python 3.11+ | python.org/downloads | Windows: tick **"Add Python to PATH"** in the installer |
| VS Code | code.visualstudio.com | |
| Git | git-scm.com | for GitHub |

VS Code extensions (Extensions panel, `Ctrl+Shift+X`):

- **Python** (Microsoft) — runs code, picks the virtual environment

## How the database supports the 3 features

- **Find a pharmacy** → `stock` links each pharmacy to each medicine with price and quantity; `pharmacies` has lat/lng for distance sorting (Phase 2).
- **Alternatives** → every medicine has `active_ingredient` + `strength` + `form`. Same three values = same medicine from another company.
- **What's inside / what it's for** → `active_ingredient` and `general_use` come from the database, not generated by AI.

# Phase 2 — Search, distance, map

## What's new

| File | What it does |
|---|---|
| `search.py` | Typo-tolerant search in English, Arabic and Kurdish; Haversine distance |
| `app.py` | New routes: `/api/search` and `/api/medicines/<id>/pharmacies` |
| `templates/index.html` | The real app page (old check page moved to `/check`) |
| `static/style.css`, `static/app.js` | Design and front-end logic |
| `static/vendor/leaflet/` | Map library, bundled locally so it works on bad Wi-Fi |

## New API routes

- `/api/search?q=panadl` → ranked matches with a score (0–100) and which field matched
- `/api/medicines/1/pharmacies?lat=35.56&lng=45.43&sort=distance` → pharmacies that have it in stock, nearest first (`sort=price` for cheapest)

## How the search works

1. **Normalize** the query and every name: lowercase, remove Arabic diacritics, and map letter variants to one form (ی/ي, ک/ك, ە/ة/ه, ۆ/و, أ/إ/آ → ا…).
2. **Score** each medicine against its brand, Arabic, Kurdish and ingredient names: exact = 100, starts with = 92, contains = 85, otherwise a similarity ratio (handles typos).
3. Keep matches scoring 60+, best first.

Distance uses the **Haversine formula** (straight-line distance on the Earth's surface).

## Demo tips

- Click anywhere on the map to set "your location". Don't rely on laptop GPS at the venue.
- The map tiles need internet. Everything else works offline.

# Phase 3 — Alternatives and medicine info

## What's new

- **Tabs** under each medicine: Pharmacies · Alternatives · About.
- **Alternatives** (`/api/medicines/<id>/alternatives?lat=&lng=`):
  - *Same medicine, other companies*: same active ingredient(s) **and** strength **and** form. A direct swap.
  - *Same ingredient, different strength or form*: shown with a warning to ask the pharmacist.
  - Combination medicines only match the exact same combination (Panadol Extra is **not** an alternative to Panadol).
  - Each alternative shows how many pharmacies have it, the nearest one, and the lowest price.
- **Sold-out banner**: if no pharmacy has the medicine, the app says so and offers a button to the alternatives.
- **About tab**: ingredients (split for combinations), strength, form, company, what it's used for, prescription note, disclaimer. All from the database, nothing generated.

## Demo scenario

`DEMO_OUT_OF_STOCK = ["Zyrtec"]` in `seed_data.py` makes Zyrtec sold out everywhere.
Search **Zyrtec** → "sold out" → **Show alternatives** → generic Cetirizine is 270 m away.
Change the list to demo with a different medicine, then run `python seed.py`.

## How matching works (`search.py`)

- `ingredient_key()` turns "Amoxicillin + Clavulanic acid" into the set {amoxicillin, clavulanic acid}, so order and spelling case don't matter.
- `strength_key()` makes "500 mg" and "500mg" equal.
- `compare_medicines()` returns `exact`, a list of differences (`strength`, `form`), or nothing.

# Phase 4 — AI scanner

## Install (once)

```powershell
venv\Scripts\activate
pip install -r requirements.txt
```
This adds **numpy**, **opencv-python-headless** (computer vision + runs the OCR neural networks)
and **zxing-cpp** (barcodes). No onnxruntime/torch needed, so it works on Python 3.15.
The OCR models (13 MB) are already in `ai/models/`.

Your box photos must be in `photo/<folder>/`, and each folder name must be listed in
`PHOTO_FOLDERS` at the bottom of `seed_data.py`.

## How to use it

Press **Scan** next to the search box.

- **Barcode:** hold the box's barcode in front of the camera. The app checks ~3 frames per
  second and opens the medicine as soon as it reads a known barcode (beep + message).
- **Recognize the box:** show the front of the box and press the button. The app reads
  the text and compares the box with your photos, then shows up to 3 answers with a
  confidence (Sure / Likely / Not sure). Click the right one.
- **Upload a photo:** same as above, from a file (or the phone camera).

The first time after starting the server, the app builds its photo index (~20–60 s).
After that it's cached in `instance/visual_index.pkl` and starts in about a second.
If you add or change photos, the index rebuilds automatically.

## How the AI works (`ai/`)

| File | Method | What it does |
|---|---|---|
| `barcodes.py` | zxing-cpp | Reads EAN-13 / Code 128 / GS1 DataMatrix. Exact. |
| `ocr.py` | Deep learning (PP-OCRv3: a DB text detector + a CRNN recognizer with CTC decoding), run with OpenCV DNN | Reads the text printed on the box. |
| `visual.py` | Computer vision (SIFT keypoints + ratio test + RANSAC homography) | Compares the image with the reference photos. Points that also appear in photos of *other* medicines (counter, pen, hand) are removed as background. |
| `recognizer.py` | Combines them | Barcode first. Otherwise each medicine gets a text score (brand name words found, fuzzy, bigger/central text counts more; generic names and wrong numbers count less) and a visual score; they're combined into one confidence. A visual match counts **alone** only with ≥20 matching points and 2× the runner-up; otherwise only as support for the text. |

API: `POST /api/scan/frame` (fast barcode check), `POST /api/scan/photo` (full recognition),
`GET /api/scan/status` (are the models loaded?). Both POSTs take an image in the `image` form field.

## Measured accuracy (`python evaluate.py`)

On the 81 photos of 16 boxes (each photo tested with itself removed from the reference set):

| Mode | Correct |
|---|---|
| Full (barcode + text + visual) | **75/81 = 93%** — 5 of the 6 misses say "not recognized" (side views), only 1 is a wrong answer |
| Box front only (no barcode) | 68/81 = 84% |
| Reading the name only (like a box we never photographed) | 49/81 = 60% (includes side/back views and Arabic-only boxes) |

False matches: with each medicine removed from the index (so its photos are "unknown boxes"),
and on the two showcase posters, the visual rule gave **0 false matches out of 42**.
About 0.9 s per photo on the test machine.

Be honest on stage: photos taken seconds apart look alike, so real accuracy with a new
camera and background will be somewhat lower. Test with your webcam before the showcase.

## Demo tips

- Good light, box about 20–30 cm from the webcam, front facing the camera.
- Barcode is the fastest and safest: start the demo with it (Gasec barcode → sold out → Ome TAD).
- Then show "Recognize the box" with a front (e.g. Fexet, Piodol), and an Arabic-only box
  (Clavmark / Claritine) to show the visual matching.
- The camera only works on `http://127.0.0.1:5000` (browsers allow cameras on localhost or https).

## Adding a new box

1. Add the medicine to `MEDICINES` (and its barcode to `BARCODES`) in `seed_data.py`.
2. Put 4–6 photos in `photo/<FolderName>/` and add `"<FolderName>": "<brand_name>"` to `PHOTO_FOLDERS`.
3. `python seed.py`, restart `python app.py`.

# Phase 5 — Pharmacist dashboard

Open **http://127.0.0.1:5000/pharmacy** (or click "For pharmacies" in the app's header).

## Demo logins

Every pharmacy has an account: username = first word of its name in lower case,
password **`pharma123`** (set in `seed_data.py` → `DEMO_PASSWORD`).
`python seed.py` prints the full list: shifa, hayat, nawroz, bakhtiari, azadi, ...
**Shifa** is the pharmacy nearest the city centre, so it's the best one to demo.

## What it does

**Overview** (choose the last 7/14 days and an area of 1/3/5 km around the pharmacy):
- Searches near you, and how many used the AI scanner.
- **Missed demand**: medicines people nearby searched for that this pharmacy doesn't have
  (not sold, or out of stock), with an "Add to stock" button.
- Searches per day, most searched medicines near you (with your stock status),
  medicines running low (≤ 5 boxes), and searches for medicines not in PharmaFind at all.

**My stock**:
- Edit price and quantity directly in the table (or with − / +). It saves by itself.
- "City average" shows how your price compares with other pharmacies (▲ above / ▼ below by more than 15%).
- Add a medicine (the city's average price is suggested), or remove one (click twice).
- Changes appear in the public app immediately, with "updated just now".

## How it works

- `pharmacy_routes.py` (a Flask Blueprint): login, stock and insights API.
- Passwords are stored **hashed** (Werkzeug scrypt), never in plain text.
- The login is a signed session cookie (`HttpOnly`, `SameSite=Lax`, 12 hours); the signing key is
  created once in `instance/secret_key`, which is not in Git.
- Requests that change data must send `X-Requested-With: fetch`, which blocks forged
  cross-site form posts. Every query only touches the logged-in pharmacy's own rows.
- The public app now sends the user's location with each search and scan; it's **rounded to
  about 100 m** before saving (`log_search` in `app.py`), which is enough for "searches near you".
- The search history in the dashboard is **demo data** (`seed_searches` in `seed.py`,
  700 searches over 14 days plus searches for medicines we don't have). Real searches you make
  in the app are added on top.

## The live demo

1. In the public app, scan or search **Gasec** → "sold out everywhere".
2. In the dashboard, log in as **shifa** → Missed demand shows *Gasec · 23 searches* → **Add to stock** → Save.
3. Back in the app, search Gasec again → Shifa Pharmacy has it, "updated just now".

Run `python seed.py` before the showcase to reset everything (Gasec sold out again).

3. Later changes: `git add .` → `git commit -m "what changed"` → `git push`. Render redeploys by itself.

## B. Render (free, always online)

1. render.com → **Get Started** → sign up **with GitHub** (no card needed).
2. **New +** → **Blueprint** → choose the `pharmafind` repository → **Apply**.
   Render reads `render.yaml`: a free Docker web service with the light AI settings
   (`PHARMAFIND_LOW_CPU=1`, 4 threads) and a random `SECRET_KEY`.
3. The first build takes about 5–10 minutes. Your address is shown at the top
   (e.g. `https://pharmafind.onrender.com`).
4. Open `https://YOUR-ADDRESS/share` → **Print**: the QR code poster for your table.

Good to know (free plan):
- It sleeps after 15 minutes without visitors; the next visit takes about a minute to wake it.
  Open it yourself a few minutes before people will use it.
- Each wake-up starts from fresh demo data (like `python seed.py`).
- 1/10 of a CPU: photo recognition takes 6–10 seconds there (the page says "still analyzing…").
  Measured with these limits: 91% correct on our photos, peak memory ~340 of 512 MB.

## C. Showcase day: fast version from the laptop

Double-click **`start_showcase.bat`** in the project folder. It:
1. resets the demo data,
2. starts PharmaFind with a real server (waitress) at `http://localhost:5000`,
3. opens a free Cloudflare quick tunnel (downloads `cloudflared` into `tools/` the first time),
4. opens the app and the **QR code page** for that run in your browser.

Visitors scan the QR code on your screen and use the fast laptop version on their phones
(https, so their cameras work). Keep the black window open; Ctrl+C stops it.
The tunnel address changes every start, so always show the QR page from the current run.
If the venue internet fails, the app keeps working on the laptop.
Try it once at home first (the first run downloads cloudflared; allow it if Windows asks).
